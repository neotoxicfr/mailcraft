# Jalon 3 — client complet

Décisions (mémoire projet, 08/11/2026) : éditeur riche de base en Rust (gras, italique, souligné,
listes, liens, taille, couleur ; envoi HTML + texte) ; rédaction dans le volet + bouton Détacher,
nouveau message en fenêtre ; images distantes affichées par défaut (bloqueur = option, désactivé) ;
Supprimer → Éléments supprimés, Maj+Suppr définitif avec confirmation, Ctrl+Z annule ; recherche
locale + « chercher aussi sur le serveur » ; autocomplétion = adresses vues + contacts Microsoft ;
« Afficher l'original » (WebView2) dans le volet de lecture.

Quatre sous-systèmes, livrés et vérifiés dans cet ordre (du moins risqué au plus risqué) :
**A. Actions et dossiers → B. Recherche → C. Lecture HTML → D. Rédaction.**

## Contraintes globales

- `unsafe_code = "forbid"` dans nos crates ; `wry`/`webview2-com` portent leur propre `unsafe`.
- Aucune police ni icône non libre ; tout glyphe affiché doit exister dans Inter ou les polices egui
  (egui panique sinon) — icônes dessinées dans `icons.rs`.
- Chaque widget interactif a un nom accessible (kittest le vérifie).
- Rien de personnel ni de secret dans le dépôt ; tests avec `example.com`.
- WebView2 : JavaScript désactivé, navigation bloquée (les liens s'ouvrent dans le navigateur
  par défaut), pas d'accès fichier.
- Toute action qui modifie la boîte passe par le worker, s'applique d'abord localement, puis est
  rejouée vers Graph ; un échec remet l'état local et s'affiche dans la barre d'état.

## Points de vigilance (et test qui les épingle)

1. **Action hors ligne ou refusée** (réseau coupé, 404 parce que déjà supprimé ailleurs) → l'état
   local ne doit pas diverger pour toujours. Test A3 : un faux client Graph renvoie une erreur,
   l'état local revient, l'action reste en file si erreur réseau, est abandonnée si 404.
2. **HTML hostile ou énorme** (scripts, `javascript:` dans les liens, 5 Mo de tableaux imbriqués,
   balises non fermées) → ni exécution, ni blocage de l'interface. Test C1 : corpus de cas,
   rendu < 50 ms pour 1 Mo, aucun lien `javascript:` ou `data:` cliquable.
3. **Éditeur : saisie au milieu d'un texte stylé, coller du HTML, emoji/accents multi-octets**
   → les styles restent alignés sur les caractères. Test D1 : propriété « longueur des styles =
   nombre de caractères » après insertions/suppressions aléatoires.
4. **Pièce jointe > 3 Mo** (limite de `sendMail`) → session d'envoi par morceaux. Test D4 :
   découpage en morceaux de 3,75 Mo (multiples de 320 Kio) vérifié sans réseau.
5. **Recherche avec caractères spéciaux FTS** (`"`, `*`, `-`, `NEAR`) → pas d'erreur SQL.
   Test B1 : requêtes piégées échappées.

## A. Actions et dossiers

- **A1 Graph** : `move_message(id, dest) -> String`, `delete_message(id)`, `set_flag(id, bool)`,
  `set_read` (existe), `create_folder(parent: Option<&str>, name) -> RemoteFolder`,
  `rename_folder(id, name)`, `delete_folder(id)`. Tests : construction des requêtes (URL, corps)
  via une fonction pure `request_for(action) -> (Method, url, json)`.
- **A2 Store** : `move_local`, `delete_local`, `set_flag`, pile d'annulation
  `push_undo(Action) / pop_undo()` (en mémoire côté UI suffit : la pile ne survit pas au
  redémarrage). Tests unitaires sur compteurs non lus après déplacement.
- **A3 Worker** : `Request::{Move, Delete{permanent}, SetFlag, SetRead{read}, CreateFolder,
  RenameFolder, DeleteFolder, Undo}` ; application locale immédiate puis Graph ; erreur réseau →
  file rejouée à la synchro suivante ; 404 → abandon + resynchro du dossier.
- **A4 UI** : sélection multiple (Ctrl/Maj+clic, Ctrl+A), touches Suppr / Maj+Suppr (dialogue de
  confirmation) / Ctrl+Z / Ctrl+Q (lu) / Ctrl+U (non lu) / Inser (indicateur) ; boutons du
  ruban actifs ; glisser des mails vers un dossier ; menu contextuel (clic droit) sur mail et
  dossier ; onglet Dossier : nouveau, renommer, supprimer (confirmation).
- **Écart (fait)** : la pile d'annulation vit dans l'UI (50 déplacements) ; Maj+Suppr est
  définitif, et Suppr dans Éléments supprimés aussi (confirmation dans les deux cas). Le test A3
  « faux client Graph » n'est pas écrit : il demanderait une abstraction du client réservée au
  jalon 4 (Gmail/IMAP) ; la file `pending` et son ordre sont testés dans le store, le reste à
  l'essai réel.
- **Fin A** : `cargo test --workspace` vert ; kittest : sélection de 2 mails + Suppr → ils
  quittent la liste, Ctrl+Z → ils reviennent ; essai réel sur le compte (déplacer, supprimer,
  annuler, créer/renommer/supprimer un dossier de test).

## B. Recherche

- **B1 Store** : migration v2, table FTS5 `search(subject, sender, preview, body)` tenue à jour
  par triggers ; `search(account, query, limit)` avec échappement (chaque mot entre guillemets,
  préfixe `*` sur le dernier). Test : requêtes piégées, accents (`unicode61 remove_diacritics 2`).
- **B2 Graph** : `search_messages(query, top) -> Vec<RemoteMessage>` (`$search="…"`, résultats
  non stockés, marqués « résultats serveur »).
- **B3 UI** : la zone de recherche interroge FTS (toute la boîte du compte, pas seulement le
  dossier) ; ligne « Chercher aussi sur le serveur » en bas des résultats ; Échap efface.
- **Fin B** : tests verts ; recherche réelle d'un mot présent seulement dans un corps déjà lu.

## C. Lecture HTML

- **C1 crate `html`** : `parse(html) -> Vec<Block>` (`Block::{Paragraph(Vec<Inline>), Heading,
  ListItem{depth, ordered}, Image{src}, Rule, Quote}`, `Inline{text, bold, italic, underline,
  link: Option<String>, color}`) via `html5ever`/`scraper` ; tableaux aplatis en lignes ; styles,
  scripts, commentaires ignorés ; liens filtrés (http, https, mailto seulement).
- **C2 Graph/Store** : corps HTML (`bodies.html`) + pièces jointes (nom, type, taille, `isInline`,
  `contentId`) ; contenu des images inline (`cid:`) téléchargé avec le corps.
- **C3 UI `reader.rs`** : affichage des blocs ; images distantes chargées par le worker (taille
  max 5 Mo, cache disque chiffré non requis : cache mémoire) sauf si le bloqueur est actif ;
  liens ouverts dans le navigateur après survol montrant l'URL réelle ; liste des pièces jointes
  avec Enregistrer / Ouvrir (boîte de dialogue `rfd`).
- **C4 WebView2** (`apps/mailcraft/src/webview.rs`) : `wry::WebViewBuilder::build_as_child` sur
  la fenêtre eframe, rectangle = volet de lecture à chaque image, masqué sinon ; HTML injecté par
  `with_html`, CSP `script-src 'none'`, navigation interceptée → navigateur. Bouton « Afficher
  l'original » / « Rendu simplifié » dans l'en-tête du mail. **Risque** : intégration fenêtre
  enfant + egui ; si elle échoue après une demi-journée, repli « fenêtre à part » (à valider
  avec l'utilisateur).
- **Fin C** : test C1 (corpus + temps) ; capture réelle d'une newsletter en rendu simplifié et
  en original ; ouverture d'une pièce jointe.

## D. Rédaction

- **D1 modèle d'éditeur** (`crates/html`) : `Doc { text: String, styles: Vec<Style> }` (un style
  par caractère), `Style{bold, italic, underline, size, color, link}`, lignes de liste préfixées
  par un marqueur ; `Doc::replace(range, text, style)` ; `Doc::to_html()` / `to_text()` /
  `from_html()`. Test de propriété (vigilance 3) et aller-retour HTML.
- **D2 widget** (`composer.rs`) : `TextEdit::multiline` avec `layouter` qui colore selon
  `styles`, diff avant/après chaque frame pour décaler les styles ; barre : gras/italique/
  souligné, puces, numéros, lien, taille, couleur ; raccourcis Ctrl+B/I/U, Ctrl+K.
- **D3 en-têtes** : À / Cc / Cci avec jetons d'adresse et autocomplétion (adresses vues +
  `GET /me/contacts`, autorisation **Contacts.Read à ajouter dans Azure par l'utilisateur**) ;
  Objet ; pièces jointes (glisser-déposer de fichiers, bouton) ; signature par compte (options).
- **D4 envoi** : nouveau → `POST /me/messages` (brouillon) puis `send` ; réponse / répondre à
  tous / transférer → `createReply|createReplyAll|createForward` puis mise à jour du corps
  (notre HTML + citation) puis `send` ; pièces jointes ≤ 3 Mo en ligne, au-delà session d'envoi ;
  brouillon enregistré automatiquement toutes les 30 s et à la fermeture.
- **D5 placement** : réponse dans le volet de lecture, bouton « Détacher » → viewport egui
  séparé (`show_viewport_deferred`) ; Nouveau courrier ouvre directement une fenêtre.
- **Fin D** : tests D1/D4 ; kittest : composer, taper, mettre en gras, vérifier le HTML produit ;
  essai réel : envoi à soi-même d'un mail mis en forme avec pièce jointe de 5 Mo, réponse,
  transfert, brouillon retrouvé dans Brouillons.
